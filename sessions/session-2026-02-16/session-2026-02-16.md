## What I understood
- Tables store data in rows and columns.
- A **primary key** is the unique ID of each row in a table.
- A **foreign key** connects one table to another table.
- `INNER JOIN` returns only the rows where there is a match in both tables.
- `LEFT JOIN` returns all rows from the left table and the matching rows from the right table.
- If there is no match in a `LEFT JOIN`, the right table columns return `NULL`.
- `RIGHT JOIN` returns all rows from the right table and the matching rows from the left table.
- A `SELF JOIN` is when a table is joined with itself.
- Using aliases like `m.title` or `b.building_name` helps specify exactly which table and column we are using.
- `WHERE` filters rows after the tables are joined.
- `ORDER BY` sorts the final result.
- `GROUP BY` groups rows that share the same values.
- `DISTINCT` removes duplicated rows from the result.

## SECTION 6: Multi-table queries with JOINs

### Find the domestic and international sales for each movie

~~~sql
SELECT 
    m.title,
    b.domestic_sales,
    b.international_sales
FROM movies m
INNER JOIN boxoffice b
    ON m.id = b.movie_id;
~~~

### Explanation
This query connects the `movies` table with the `boxoffice` table.

It only shows movies that have matching box office information.

---

### Show the sales numbers for each movie that did better internationally than domestically

~~~sql
SELECT 
    m.title,
    b.domestic_sales,
    b.international_sales
FROM movies m
INNER JOIN boxoffice b
    ON m.id = b.movie_id
WHERE b.international_sales > b.domestic_sales;
~~~

### Explanation
This query shows only the movies where international sales were higher than domestic sales.

---

### List all the movies by their ratings in descending order

~~~sql
SELECT 
    m.title,
    b.rating
FROM movies m
INNER JOIN boxoffice b
    ON m.id = b.movie_id
ORDER BY b.rating DESC;
~~~

### Explanation
This query joins movies with their ratings and sorts the result from highest rating to lowest rating.

## SECTION 7: SQL Lesson 7: OUTER JOINs

### Find the distinct buildings that have employees

~~~sql
SELECT DISTINCT
    b.building_name
FROM employees e
LEFT JOIN buildings b
    ON e.building = b.building_name;
~~~

### Explanation
This query shows the buildings connected to employees.

`DISTINCT` removes repeated building names.

---

### Find the list of all buildings and their capacity

~~~sql
SELECT 
    building_name,
    capacity
FROM buildings;
~~~

### Explanation
This query does not need a join because all the information is already inside the `buildings` table.

---

### List all buildings and the distinct employee roles in each building, including empty buildings

~~~sql
SELECT DISTINCT
    b.building_name,
    e.role
FROM buildings b
LEFT JOIN employees e
    ON b.building_name = e.building
ORDER BY b.building_name, e.role;
~~~

### Explanation
This query starts from `buildings`, so every building appears even if it has no employees.

If a building has no employees, the employee role will appear as `NULL`.

## Interview Question: Page With No Likes

### Problem
Find all pages that have no likes.

~~~sql
SELECT 
    p.page_id
FROM pages p
LEFT JOIN page_likes pl
    ON p.page_id = pl.page_id
WHERE pl.page_id IS NULL;
~~~

### Explanation
This query starts from the `pages` table and tries to match each page with the `page_likes` table.

If a page has no matching likes, then `pl.page_id` will be `NULL`.

So this condition:

~~~sql
WHERE pl.page_id IS NULL;
~~~

keeps only the pages with no likes.
